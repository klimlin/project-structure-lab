# Обоснование структуры проекта

Выбрана классическая структура для Python-приложения:

- `src/` — исходный код изолирован от конфигурационных файлов в корне;
- `tests/` — автотесты отделены от кода, чтобы не попадать в сборку;
- `docs/` — документация и обоснования архитектурных решений;
- `assets/` — статические ресурсы (изображения, шрифты);
- `.github/workflows/` — место для конфигурации CI (GitHub Actions);
- `README.md`, `.gitignore`, `LICENSE` — стандартные файлы корня репозитория.

Такая структура соответствует рекомендациям Python Packaging Authority (PyPA)
и упрощает автоматизацию: тесты запускаются из `tests/`, код — из `src/`.
